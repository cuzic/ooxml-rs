# PR #130 レビュー（Opus, round 1）

対象: docs/cleanup-after-merge @ da02bf0aecd51714b4a029e2c459420238cf8cc2

## 結論（先に）
片付けの方針自体は妥当だが、merge-pr 手順 7 の「消してよい」条件が、マージした PR とは無関係の
作業中のディレクトリを拾える。特に、作ったばかりの worktree / クローン（HEAD がまだ `origin/main`、
未追跡ファイルだけがある）と、Codex がしばらく触っていない `/tmp` の作業クローンで、未 push の作業を失いうる。
converged: no（Major 2）。

## 前ラウンドの解消状況
round 1 のため無し。

## Findings

### M1（Major）: 手順 7 の条件が「この PR のもの」に絞られておらず、着手直後の作業を消せる
- 根拠: `.claude/skills/merge-pr/SKILL.md` 75–79 行。条件は「HEAD が `origin/main` に含まれる・未コミットの変更なし・
  どのプロセスも使っていない」だけで、2 つ目の箇条（`rev*` `review*` `cx-*` のクローン）は PR で絞っていない。
  - `git worktree add -b impl/x <path> origin/main` や、新しい ADR を書き始めたばかりの main のクローンは、
    コミット前なら HEAD が `origin/main` に含まれるので条件を満たす。
  - エージェントの Bash 呼び出しはコマンドごとに終わるので、呼び出しの合間には cwd を持つプロセスが無い。
    「使用中」は、作業中かどうかの判定に使えない。
  - 「未コミットの変更」に未追跡ファイルを含むかが書かれていない。owner の hook（リポジトリ外）はクローンを
    `git status --porcelain --untracked-files=no` で判定するので、まだ `git add` していない新規ファイル
    （書きかけの ADR やレビューファイル）は消える。hook は worktree も、マージした PR に関係なくすべて調べる。
- 修正案: 消す対象を「マージしたブランチを checkout している worktree / クローン」に限り、未追跡ファイルも
  変更として数える（`git status --porcelain` を既定のまま使う）と書く。それ以外は消さずに報告だけにする。
  hook も同じ条件に合わせる。

### M2（Major）: `/tmp/ooxml-*` の「この PR の分」を見分ける方法が無く、hook は経過時間だけで消す
- 根拠: 同 79 行。Codex は sandbox で `.git` が読み取り専用なので `/tmp` の一時クローンで作業し、
  そのクローンは別の PR のレビュー待ちの間も残っている。手順には「この PR の分」をどう見分けるかが無い。
  owner の hook は、git の状態を見ずに「120 分触っていない・プロセスが使っていない」で `/tmp/ooxml-*` を
  `rm -rf` する。レビュー待ちで止まっている別 PR の Codex クローンに未 push のコミットや未コミットの変更が
  あれば失われる（重大度表の「データを黙って失う」）。
- 修正案: `/tmp` の作業ディレクトリが git クローンなら M1 と同じ条件（マージしたブランチ・HEAD が main に含まれる・
  未追跡を含めて clean）で判定する。git でないもの（`CARGO_TARGET_DIR` など）は PR に紐づく名前のときだけ消す。
  これを手順に書き、hook もこの条件に合わせる。

### m1（Minor）: AGENTS.md の新しい規則に、消してよいかの確認が無く、対象もはっきりしない
- 根拠: `AGENTS.md` 50–52 行。「PR を作るか更新して報告を書いたら消す」としか書かれておらず、push 済みで
  clean であること（`git status --porcelain` が空、`git log @{u}..` が空、ほかのローカルブランチや stash が無い）を
  確かめる手順が無い。「作業用のクローン」に、作業ごとの `git worktree`（Git の約束 62 行）が含まれるのかも
  読み取れない。merge-pr 手順 7 は「Codex の `/tmp` 作業ディレクトリはマージ後まで残っている」前提で書かれており、
  二つの規則がずれている。
- 修正案: 「push 済みで、上の確認が空のときだけ消す」と書く。worktree はマージ後に merge-pr 手順 7 で消すことにして、
  この規則の対象から外す。

### m2（Minor）: build target が共有されている場合に、他のエージェントのビルドを壊す
- 根拠: `AGENTS.md` 50 行、`review-pr/SKILL.md` 76 行、`merge-pr/SKILL.md` 78 行。複数の作業で 1 つの
  `CARGO_TARGET_DIR` を共有していると、それを消したときに並行して動いているビルドが失敗する。
- 修正案: 「自分がこの作業のために作った target だけを消す」と書く。

### m3（Minor）: hook が動くタイミングが手順の順番と違う
- 根拠: 同 81 行。hook は `gh pr merge`（手順 4）の直後に動くので、手順 5 の付け替えとブランチ削除より先に片付けが
  終わる。しかし手順 7 は手順 5 の後に書かれている。hook がリポジトリに含まれず、hook の無い環境では動かないことも、
  読み手からはわかりにくい。
- 修正案: 「hook のある環境では手順 4 の出力に片付けの結果が出るので、それを読んで手順 7 の報告に使う」と書く。

### n1（nit）: `git branch -d` が拒否したときの扱いが書かれていない
- 根拠: 同 77 行。手順 5 でリモートブランチを消した後は、`-d` が現在の HEAD を基準に判定するので、ローカルの main が
  古いと拒否される。
- 修正案: 「拒否されたら `-D` にせず、残したものとして報告する」と書き足す。
